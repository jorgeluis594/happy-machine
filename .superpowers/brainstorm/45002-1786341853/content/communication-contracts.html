Comunicación durable entre estados

Markdown puede ser contenido; la memoria puede ser caché. Ninguno debería ser el protocolo durable.

Estado A / Orca
produce resultado + archivos
→ResultEnvelope
Motor durable
valida · persiste · decide transición
materializa la siguiente entrada
→InputEnvelope
Estado B / Orca
recibe contexto preparado
Base durable — fuente de verdad

Ejecuciones, estados, intentos, eventos, outcomes y referencias. SQLite inicialmente.

Artefactos — contenido

Markdown, código, imágenes y archivos grandes, identificados por referencias estables.

Memoria — descartable

Cachés, procesos activos y límites de concurrencia. Todo se reconstruye al reiniciar.

Salida del estado A

{
  "status": "completed",
  "outcome": "needs_revision",
  "data": { "score": 0.55 },
  "artifacts": [
    { "ref": "artifact:feedback.md" }
  ]
}

Entrada materializada para B

{
  "state": "redactar",
  "attempt": 2,
  "data": { "topic": "..." },
  "artifacts": [
    { "role": "feedback", "ref": "..." },
    { "role": "previous_draft", "ref": "..." }
  ]
}
Regla: A nunca escribe directamente en B. A entrega un resultado al motor; el motor lo confirma y construye la entrada inmutable de B.
